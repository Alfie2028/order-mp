# 设计文档与版本记录

校园多档口点餐（uni-app 小程序 / H5 + FastAPI 后端）
当前版本：**v1.1.0**，标签 `v1.1.0-20261109`，对应提交 `81371d6`。

## 1. 设计目标

在不改后端结构、不新增大依赖的前提下，把一个"接口曾失效、页面组织松散"的校园点餐项目整理成可稳定演示、答辩讲得通的产品：

1. 页面结构清晰：四个主入口 + 业务子页，入口与出口一一对应；
2. 数据来源明确：线上接口为准，本地目录仅作兜底与展示补全；
3. 视觉统一紧凑：蓝白暖金变量体系，首页信息密度提高但不拥挤；
4. 主流程完整：选门店 → 选档口 → 选餐品规格 → 购物车 → 结算 → 订单状态；
5. 每个改动都能用运行时截图与构建产物双向核对。

| 层级 | 页面 | 职责 |

## 3. 数据模型与数据流

### 3.1 层级

门店（stores）→ 档口（stalls，`store_id`）→ 餐品（products，`stall_id`）→ 购物车 / 订单（`order_items` 记录商品与规格）。优惠券分平台券（`coupons`）与用户领取记录（`user_coupons`）。共 3 家门店、6 个档口、25 道餐品。

### 3.2 读取链路

```
页面 → store/app.js → utils/request(get)
  ├ /api/catalog/stores
  ├ /api/catalog/stalls
  ├ /api/catalog/products
  └ /api/catalog/coupons
        ↓ 成功                       ↓ 失败
  state 用接口数据（snake_case→camelCase）   state 沿用 src/data/catalog.js 本地目录
```

- 映射函数：`mapStore / mapStall / mapProduct / mapCoupon`；本地目录同时为接口数据补齐 `badge`、`featured`、图片占位字等纯展示字段。
- 结论：**餐品与档口的归属关系由后端决定，前端不硬编码商品**；本地目录是离线兜底，不作为线上真值。

## 4. 关键业务规则

### 4.1 点单页分组展示

- 上段「本档口餐品」：`stallId` 等于当前档口，顺序按后端返回。
- 下段「同店其他档口 · 也受欢迎」：从其余档口按销量降序取 6 道，排除本档口已有与售罄（`isActive === false`）的商品。
- 单页合计 10 道；标题计数与分组合计一致。
- 借来的卡片仍显示真实 `stallName`，加购与下单使用原 `productId`，落到原档口，不产生跨档口错误数据。
- 搜索不受分组影响：输入关键词时按名称 / 副标题 / 角标 / 档口名全量检索。

### 4.2 在线客服

点「在线客服」先弹说明（标题「校园餐厅客服中心」，正文含热线 400-800-1234、受理时间 07:30–21:30（节假日正常）、咨询范围），点「拨打」调 `uni.makePhoneCall` 唤起系统拨号盘；取消只做轻提示。客服卡小字同步显示热线号。号码为演示用途。

### 4.3 首页

- 轮播与顶部状态胶囊分离：顶部只保留右侧「营业中 · 07:30–21:30」，不显示门店定位文字。
- 搜索框独立成行（sticky），不叠加在轮播图上；原「商家配送 / 到店自取」双模卡已移除，取餐方式改在结算页选择。
- 十格金刚区 → 均映射到具体档口；美食节 banner 与券卡 / 秒杀卡复用肥嘟嘟母版版式；「吃货券包」区块已删除，餐品列表整体上移。

### 4.4 支付与订单

支付、订单状态推进、签到、热量估算为本地演示实现，不接真实渠道；订单状态可手动推进以便演示完整生命周期。

## 5. 视觉规范

- 主色 `--brand` 深海蓝，辅色暖金 `--caramel` 与燕麦底 `--oat`；卡片圆角 20–26rpx，主按钮 18rpx。
- 首页：白底卡片 + 绿色美食节 banner（`#14a06b → #0a7a52`）+ 蓝色品类区，信息分块不混排。
- 点单页：左栏浅灰 `#f2f3f5` 选中态白底 + 左侧蓝条；分组之间用虚线分隔，标题带品牌色短竖条。
- 我的页：蓝色渐变头部 + 白色浮层统计卡 + 蓝色服务图标。
- 字号：正文 22–26rpx，辅助 18–20rpx，金额 30–36rpx 加粗。

## 7. 验证方式

- 构建：`npm run build:mp-weixin` 通过，产物位于 `dist/build/mp-weixin`；老版本产物目录已清理。
- 运行时：微信开发者工具 + `miniprogram-automator` 读取页面数据与文案，逐轮截图核对（首页去定位、客服弹窗与拨号、点单页 10 道分组）。
- 产物核对：源码、`dist` 产物、运行时三者文案一致；若不一致先查构建产物，再清开发者工具编译缓存（`User Data\<hash>\WeappCache`）。

## 8. 已知边界

- H5 在本机曾出现白屏（TDZ 类报错），演示以微信开发者工具 / 真机为准。
- 地图为平台原生组件，距离、出餐时间为配置值，不含真实路线导航。
- 客服热线、支付、订单流转、签到、热量估算均为演示实现。
- 商家侧页面面向演示，未做权限分级与真实库存同步。
