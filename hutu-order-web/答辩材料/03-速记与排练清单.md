# 校园点餐答辩｜速记与排练清单

[返回材料索引](00-索引.md) · [完整讲解稿与演示路线](01-答辩讲解与演示.md) · [36 题问答](02-常见问题与参考回答.md)。

## 1. 开场 30 秒

老师好，我的课程设计是基于 uni-app 与 Vue 3 的校园多档口点餐应用。项目包含门店选择、档口浏览、餐品规格、购物车、结算和订单查询。当前有 3 家门店、6 个档口、线上 25 道餐品，点单页每档展示 10 道（本档 + 同店推荐），主要使用 Vue 响应式状态、组件通信、uni-app 页面路由实现完整交互，支付与订单流转采用模拟方式。

## 2. 最先记住的 12 个回答

| 问题 | 一句话回答 | 本项目证据 |
| --- | --- | --- |
| Vue 和 uni-app 什么关系？ | Vue 组织组件与响应式，uni-app 提供跨端组件、API 与构建 | `.vue` 页面、`uni.navigateTo` |
| 页面怎么组成？ | 9 个页面，4 个主 tab：首页、点单、餐厅、我的 | `pages.json` |
| 数据哪里来？ | 目录在 JS 文件，运行状态在内存与本地缓存 | `catalog.js`、`store/app.js` |
| `ref` 和 `reactive`？ | ref 包装值，脚本用 `.value`；reactive 代理对象 | 搜索词与共享 state |
| 总价怎么自动更新？ | `computed` 根据单价和数量推导 | `cartSubtotal` |
| 父子怎么通信？ | props 向下传，emit 通知父组件 | `ProductCard` |
| `onLoad` 与 `onShow`？ | 加载接收参数；显示时可再次检查状态 | 详情页、结算页 |
| 页面如何跳转？ | 详情 navigateTo，主 tab switchTab，下单后 redirectTo | 点餐与结算页面 |
| 刷新后为什么还在？ | 操作后写缓存，启动时读缓存 | `persist`、`initializeStore` |
| 金额为什么用分？ | 以整数计算，显示时转元 | `priceCents`、`formatMoney` |
| 支付是真的吗？ | 本地延时后建单，没有真实渠道调用 | `submit`、`createOrder` |
| 一套代码怎么跨端？ | 基础逻辑复用，差异使用条件编译并分别验证 | H5 iframe / 非 H5 map |

## 3. 演示只走一条完整路径

首页 → 点单 → 黑椒鸡腿饭标准份加蛋 → 河南烩面标准份无加料 → 购物车 → 农大校园券 → 确认支付 → 状态推进 → 历史订单 → 刷新恢复。

金额：`18.80 + 2.00 + 18.80 = 39.60`，校园券减 `6.00`，实付 `33.60`。

初始数据下，下单后共 3 单、1 张券、893 积分。订单号和取餐码不固定。取餐方式可以保留到店自取。

时间紧时保留选规格、购物车、下单与订单四个步骤。地图与会员服务不占主要演示时间。

## 4. 三段代码必须能讲

第一段：`src/pages/item-detail/index.vue` 的 `onLoad` 和 `unitPrice`。输入是路由 id 与所选规格，输出是当前餐品和计算后的单价。

第二段：`src/store/app.js` 的 `addToCart` 和 `cartSubtotal`。输入是商品 id、规格和数量，结果是更新共享购物车，并让界面重新显示数量与金额。

第三段：同文件的 `createOrder` 和 `persist`。流程是读取购物车、计算优惠、复制明细、保存订单、更新券与积分、清空购物车、写入缓存。

## 5. 不要说错的 10 件事

1. 没有用 Pinia、Vuex、MySQL 或真实业务后端。
2. 真实支付、登录认证、库存和商家后台尚未接入。
3. 浏览器手机尺寸是 H5 预览，不是微信小程序真机。
4. 小程序构建通过不代表所有设备和 API 已验证。
5. 默认校园坐标和距离来自配置，不是实时 GPS 距离。
6. 餐厅共用菜单，没有真实多商户拆单与独立结算。
7. 订单“刷新”按钮推进本地状态，没有向服务器刷新。
8. 本地缓存不是可靠数据库；更换浏览器或站点地址不会自动同步。
9. 首页推荐是静态筛选；客服、开票等部分入口只是提示。
10. 课程要求、个人工作量与 AI 辅助使用据实说明，不能用材料替代实际理解。

## 6. 答辩前运行准备

已有依赖时，在项目根目录运行：

```powershell
npm run dev:h5
```

打开终端实际显示的地址；通常为 `http://localhost:5173/`。展示过程中统一使用同一地址。首次安装或换电脑时先执行 `npm install`，提前完成安装，避免把网络依赖留到现场。

浏览器切换移动设备视口，建议先按 390 × 844 检查。确保文字、底部按钮和页面滚动正常。终端保持运行。

需要微信开发者工具演示时，先执行：

```powershell
npm run build:mp-weixin
```

导入 `dist/build/mp-weixin`，按目标平台要求配置并测试。若现场没有开发者工具，明确展示的是 H5 版本，不承诺现场临时补成真机演示。

需要重新检查生产构建时执行 `npm run build:h5`。H5 开发预览和 H5 生产包是两种运行方式，不要把构建完成误认为已经自动部署上线。
